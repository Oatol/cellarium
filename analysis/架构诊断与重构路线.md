# 架构诊断与重构路线

> 编制于 2026-11-28。基于 Cell Lab 反编译源码（`analysis/cell_lab_apk_extract/decompiled_zh/`）、Alien（chrxh/alien）、Bioneers（Steam 3833810）与现有工程代码的对照。
> 结论：现有架构存在结构性过度设计，即使照抄 Cell Lab 的机制也不该这么慢。可以大改。

## 0. 量化差距（最硬的证据）

## 1. 五个结构性问题

### 问题一：碰撞求解过度刚性（最大头，占 3000 细胞 43%）

| | 本项目 `resolve_collisions`（native/src/cell_spatial.cpp:281-353） | Cell Lab `c(boolean,double)` + 速度积分（CellWorld.java:1346-1400, 898-967） |
| --- | --- | --- |
| 迭代 | **6 轮** + 每 3 轮 `build_pairs()` 全量重建网格 | **单轮**，每对只处理一次（`i7 > i`） |
| 邻居来源 | 全局 `std::vector<int> pairs` 动态分配 | 固定容量网格 `aV[格][203]`，就地遍历 |
| 修正方式 | **直接改位置**（Gauss-Seidel），位置变了必须重建网格 | 相交面积算**软弹力**，力累积到速度 `cell.g += d60`，位置下一阶段积分 |
| 距离判据 | 每 pair `std::sqrt` | 先用 `d46 < d49*d49` 比平方，确认重叠才 sqrt |

**根因**：本项目追求"单帧刚性收敛"，所以 6 轮迭代 + 位置直接修正 + 重建网格。Cell Lab 用"软弹力 + 速度累积 + 时间自然分离"，单轮就够，视觉上细胞本来就是软的。**这是 6× 起步的结构性浪费。**

### 问题二：数据布局 SoA + 动态字符串访问

- 本项目：SoA 列（`CellArray.gd:13-51`），热路径每 tick 多次 `cells.get("cell_pos_x")` 动态调用 + PackedArray COW 语义。
- Cell Lab：AoS 紧凑 `Cell` 对象 + 固定容量池 + 尾槽换删（`x[i].a(x[z-1]); z--`），全程不 new。
- 影响：缓存局部性差、GDScript→native 胶水开销、跨线程 COW 撕裂风险（B3 已踩坑）。

### 问题三：缺少"昂贵逻辑降频 + 每对象工作量硬上限"

- Alien：`TIMESTEPS_PER_CELL_FUNCTION=6`（神经/基因每 6 tick 算一次）、`MAX_OBJECT_CONNECTIONS=6`、`NEURAL_NET_INPUTS=16`——给每对象工作量设硬上限，昂贵逻辑错峰。
- 本项目：1× 时每 tick 全量 behavior/physics/metabolism；LOD 只在 ≥8× 降频。连接上限 20（与 Cell Lab 同），但**没有神经/行为的固定降频**。
- 影响：低倍速也背满额成本；神经 84ms/3000 细胞（28µs/细胞）远超理论值，说明间接开销巨大。

### 问题四：GPU 几乎闲置

- Alien：CUDA Graph 整步发射（`physics_fillGrids → ... → cell function → structuralOperations`），全程 GPU，每步只同步一次。
- 本项目：GPU 只做环境场扩散/采样（`EnvironmentField.gd`），behavior/physics/metabolism 全在 CPU。
- 影响：浪费 GPU 算力——这正是你最初的判断。

### 问题五：模拟与渲染未真正解耦

- Cell Lab：单后台线程 `ThreadPoolExecutor(1,1)` 跑 update1/update2，渲染线程只做 GL，`Thread.sleep` 锁 60fps。
- Alien：`EngineWorker::runThreadLoop()` 独立线程，默认与渲染解耦。
- 本项目：主线程 tick；B3 的 worker 只是把整个 tick 搬到另一线程，**没解决单 tick 成本**（实测 512 仅 1.21×）。

## 2. 重构路线（按 ROI 排序）

### 阶段 1：碰撞内核重构 —— Cell Lab 式单轮软弹力（最高 ROI）—— **已完成 v0.47.0**

- 把 `resolve_collisions` 从"6 轮迭代 + 重建网格 + 直接位置修正"改为"单轮遍历固定网格 + 相交面积软弹力 + 力累积到速度"。
- 预期：3000 细胞碰撞 108ms → **15–25ms**（参考 Cell Lab）。
- 代价：物理手感变"软"（Cell Lab 就是这个手感，可接受）；**state hash 必须重建**（物理结果不同）。
- 确定性：软弹力用 double 累积、遍历顺序固定，可保同种子可复现。

**落地结果（2026-11-28，v0.47.0）**

实际收益远超预期，且关键杠杆不是"去掉 6 轮迭代"，而是**网格尺寸**：

| 项 | 旧路径 | 新路径 | 倍数 |
| --- | --- | --- | --- |
| 微基准 1024 细胞（等密度） | 1732.3 µs | 71.7 µs | 24.2× |
| 微基准 3000 细胞 | 9367.8 µs | 229.0 µs | 40.9× |
| 微基准 5000 细胞 | 22990.2 µs | 407.0 µs | 56.5× |
| **真实皿 1024 细胞 `phys_collision`** | 1795.1 µs | **109.5 µs** | **16.4×** |
| **真实皿 1024 细胞整 tick 墙钟** | 8800.6 µs | **6869.0 µs** | -21.9%（TPS 113.6→145.6） |

1024 细胞整 tick 墙钟**首次进入 8 ms 预算**（6.87 ms）。碰撞占整 tick 从 20.4% 降到 1.6%，不再是主项。

**分解收益来源（重要，避免后续误判）**：

1. **网格尺寸**（最大单项，约 2.5×）：旧路径 `cell_size` 写死 64.0，而典型细胞直径只有 14。每个桶挤约 20 个细胞，9 格邻域要扫 180 个候选，其中只有约 6 个是真邻居 —— 30× 无效扫描。改为按 `2 × cell_radius × 最大半径倍率` 自动推导（1024 细胞时 13.28，3000 细胞时 7.76）。
2. **去掉 6 轮迭代 + pairs 物化**（约 6×）：单轮遍历，不建 pairs 向量，省掉每 tick 数万次 `push_back`。
3. 两者相乘即 20–50×。

**手感验证**：软弹力最坏重叠 4.62 单位，旧路径 8.44（contact = 14）；平均重叠 0.679 vs 0.437，差 1.7%，肉眼不可辨。细胞数与总能量两条路径完全一致。`COLLISION_SOFTNESS=1.0`（每 tick 消除一半穿透）。

**未做但值得做的后续**：真实"力累积到速度"（Cell Lab 的 `cell.g += d60`）没有采用，改用了位置投影 + 部分修正。原因是本项目 Verlet 的速度是 `pos - prev` 派生，直接投影位置在 PBD 语义下已经等价于注入速度，且比显式冲量更稳定（不会因穿透深度大而爆能量）。若后续上 GPU，才需要显式的速度累加形式。

### 阶段 2：消除场采样的重复 GPU 往返（中等 ROI，已完成 v0.48.0）

原计划是"热路径 AoS 化"。真实窗口分段推翻了这个判断：**阶段 1 之后，真实窗口下最大单项不是逐细胞算术，而是场采样的两次 GPU 往返**。一个 tick 里两次按细胞采样用的是同一份场状态（`advance_field_tick` 在整个 `advance_physics_tick` 之后才推进），旧路径却付了两次 `submit()+sync()`，每次约 967 µs。

已落地（v0.48.0）：整场 `5R²` 一次回读 + `CellSpatial.sample_fields_nearest()` 两次本机查表；回读放在 `diffuse_tick` 的 sync 之后（比延迟到下次采样便宜 5.2×）。真实窗口同机背靠背 tick1 p50 −24.9%、tick3 −27.4%，`setup_dispatch` 9823.9→112.1 µs。详见 `CHANGELOG.md` v0.48.0。

**AoS 化本身仍未做**：`metab_env` / `metab_base` 剩余开销是纯 GDScript 逐细胞算术（v0.41/v0.44/v0.45 已把字典查找与边界检查逐项拆掉），AoS 紧凑结构只在配合 C++ 下沉时才有意义，单靠 GDScript 改数据布局收益有限。

### 阶段 2.5：那一次整场回读本身（新出现，最高单项）

`PART field` avg 7878.9 / p50 3480 µs，主体是 `buffer_get_data` 的 20 KB 等待。要再降只有两条路：把场整体移出主 tick 关键路径（阶段 4 / 阶段 B 独立模拟线程），或降低场推进频率（会改语义，需单独评估）。

### 阶段 3：调度层 —— 昂贵逻辑降频 + 工作量硬上限（低成本）

- 参考 Alien `TIMESTEPS_PER_CELL_FUNCTION=6`：神经/行为按固定间隔更新，中间 tick 复用（已有 `should_update_neural` 机制，但只在 ≥8× 生效；可改为全档位固定间隔）。
- 每细胞接触数硬上限（已有 20，可降到更合理的值）。

### 阶段 4：GPU 主体化（长期，最大工程）

- 参考 Alien CUDA Graph：behavior（纯 SIMD，8→4→6 网络）+ collect_inputs_grid（整数邻域计数可保位）搬 GPU compute。
- 需重建 hash 基线；collision 的 Gauss-Seidel 依赖已在阶段 1 消除，GPU 化前提已具备。

## 3. Bioneers 的定位

Bioneers（Steam 3833810，Azza Apps）是"工厂建造 + 器官模拟"玩法向参考：细胞类型（muscle/skin/fat/bone/nerve）连成呼吸/消化/排泄系统 + 神经系统。系统要求 i5-10400F + GTX 1050 Ti，是**中小规模、器官级**模拟，不是几千细胞粒子模拟。**技术架构参考价值有限**，但对本项目的"细胞类型分化 + 器官系统 + 神经网"玩法完成度有直接参考。

## 4. 建议的第一步

先做**阶段 1 碰撞内核重构**：它是 3000 细胞最大单项（108ms/43%），且是超线性爆炸的根源。先在一个隔离原型里实现 Cell Lab 式单轮软弹力，与现有多轮路径做 A/B（同细胞数、同密度），测真实加速比 + 视觉稳定性，再决定是否落地生产 + 重建 hash 基线。

**注意**：这是玩法手感 + hash 基线双重变更，需你确认"接受软弹力手感 + 重建 hash 基线"后才落地生产代码。

## 5. 连接模型：先照 Cell Lab 落地，为 Alien 角序留口

**两家都会断**（这是"该不该复刻"的答案，源码已核）：

| | 静止/键长 | 断裂阈值 | 换算成直径 |
|---|---|---|---|
| Cell Lab | 中心距 ≈ `1.2r`（端点重合） | 端点距 > `2·max(r)` | ≈ 1.6 倍 |
| Alien | `connections[i].distance`（创建时写入） | `maxBindingDistance` 默认 3.6 | ≈ 1.8 倍 |

落地顺序不能颠倒：**静止长度改为每 tick 由当前半径派生 → 求解器换软弹簧 + 端点相对速度阻尼 → 再加撕裂**。硬投影阶段直接挂阈值会在单帧大位移时把生物撕碎。

**给 Alien 角序留口的具体做法**：`CellArray` 里连接表保持「每对连接一条、扁平、无序」。Alien 的 `angleFromPrevious` 环形角序是**每 tick 从扁平表按 (cell_index, 局部角) 排序派生出来的视图**，不进存储层。以后要上 Alien 模型，只需新增派生层 + 角约束求解，不动 `CellArray` schema、不动存档。

**禁止**：为了"省一次排序"把连接在细胞上的顺序写进 `CellArray`。那会把角序模型锁死在存储层，等于提前排除 Alien 路线。

## 6. 渲染：Cell Lab 不切 Canvas，因为它根本不在 CPU 造几何

Cell Lab（`CellWorld.a(float[])` / `b()` / `c()`，约 3695–3790 行）只有一条渲染路径：

- 每个对象往三组扁平数组写 **固定 6 个顶点**（`ah` 单位 quad 角、`ai` 世界中心、`aj` 颜色 RGBA）；
- 一次 `glDrawArrays(GL_TRIANGLES, 0, be)` 提交全部细胞，超过 32766 顶点才分批（16 位索引上限）；
- 圆、膜、接触弦、细胞器全部在 **fragment shader** 里由 quad + 中心 + 半径算出来；
- 全代码没有任何按缩放或细胞数切换的分支（`this.e.k` 无比较，`be/bf/ap` 只是顶点计数）。

**所以"细胞再多 Canvas 也不变"不是优化技巧，是它压根没有 per-cell 对象，也没有 CPU 几何。** 顶点数只随细胞数线性增长，管线恒定。

本项目两条路径都是在 CPU 上造几何，各有各的贵法：

- 逐实例档：每细胞 9 个绘制型 CanvasItem（Body / InnerRing / Nucleus / Outline / 5×Organelle）+ 2 个非绘制节点，48 段轮廓 → 节点数 × 段数双重爆炸；
- 三角批档：1 个 CanvasItem，但每帧在 CPU 逐细胞裁弦 + 三角展开，`FrameProfiler.cache` 在 1025 细胞是 p50 **8.5ms**，已是渲染侧头号单项。

**结论**：删 `max_instances` 切换是必须的（外观突变本身就是错的），但只删切换只是把「节点爆炸」换成「CPU 三角爆炸」。真正的统一要把膜与细胞器搬进 shader，做到每细胞顶点数恒定，才和 Cell Lab 同构 —— 顺带把 8.5ms 的 `cache` 打下去。分两步：先补齐单 CanvasItem 档的功能（细胞器/信号锚点）并删切换，再迁 shader。

### 6.1 第一步已落地（v0.52.0）

`CellSceneRenderer` 删除 `max_instances=48` 阈值分支，生产路径与细胞数无关；逐实例档降级为 `use_instance_path`（默认 false）调试开关。SmokeTest 三个 CellView 用例显式打开调试档。

生产路径的选择：`shader_layer != null and ClassDB.class_exists("CellRenderCache")` 成立走 `CellMembrane`（shader 层），否则退回 `CellBatchPoly`（单 CanvasItem 三角批）。回退分支保留的理由是 GDExtension 可能缺失（用户在无编译环境的机器上直接跑工程）—— 这是**降级路径**，不是第二套生产画法，两者外观同构（同一份 `cell_params` 语义：体 / 轮廓 / 内膜环 / 核 / 细胞器）。

### 6.2 第二步已落地（v0.52.0）

`shaders/cell_membrane.gdshader` + `tools/ShaderMembraneProbe.gd`（`checks=7 failures=0`）证明：

- Godot 4 `canvas_item` shader **可以**拿到 `INSTANCE_CUSTOM`（要在 `vertex()` 里转成 varying 传给 `fragment()`）；
- 用 RGBA32F 的 1 行参数纹理（每细胞 16 texel）可以喂够每细胞参数：body / outline / nucleus / organelle 四组颜色 + 最多 8 条接触弦 + 5 个细胞器偏移；
- 用有符号距离 `sd = max(length(p)-1, 各弦半平面距离)` 一次算完「被弦切平的膜」，`fwidth` 做抗锯齿；外轮廓画在 `|sd| < w` 上，所以**弦面也有边，接触处不缺边**；
- 每细胞只提交一个 quad（6 顶点），细胞器、内膜环、核全部在 fragment 里判定，**per-cell 顶点数恒定**。

剩余工作：`cache` 的实测收益尚未在真实窗口基准里量（`build_geometry=false` 跳过了整段三角展开，预期是 `FrameProfiler.cache` 那 8.5ms 的主体，但必须同会话 A/B 才能宣称）。

**接入链路（已落地）**：

```
OrganismManager ──► CellRenderCache::rebuild(..., build_geometry = false)
                        │  只产 cell_params / count / centers / radii
                        ▼
              CellShaderLayer (MultiMeshInstance2D)
                        │  每实例 6 顶点 quad + INSTANCE_CUSTOM = 细胞下标
                        │  RGBA32F 参数纹理（每细胞 16 texel，宽度 = capacity × 16）
                        ▼
              cell_membrane.gdshader (fragment)
                        │  sd = max(length(p)-1, 8 条弦半平面) + fwidth 抗锯齿
                        ▼  体 / 轮廓 / 内膜环 / 核 / 5×细胞器
```

**参数纹理布局**（`PARAM_TEXELS = 16`，RGBA32F）：

| texel | 内容 |
| --- | --- |
| 0 | 体色 RGB + alpha |
| 1 | 轮廓色 RGB + alpha |
| 2 | 细胞核 RGB + alpha |
| 3 | 细胞器 RGB + 数量（`count / MAX_ORGANELLES`） |
| 4–7 | 最多 8 条接触弦，偶 texel `a.xy, b.zw`、奇 texel `b.xy, a.zw`（归一化到半径） |
| 8–12 | 5 个细胞器 `(cos·dist, sin·dist, size_ratio, 0)` |
| 13–15 | 预留（当前写 0） |

**踩坑（都已修，后续改 shader 会再遇到）**：

1. `INSTANCE_CUSTOM` 在 `fragment()` 里直接读恒为零，必须在 `vertex()` 转成 varying。
2. `half_plane()` 的法线要保留**包含原点的那一侧**：`if (dot(-a, n) > 0.0) n = -n;`。写反会让细胞中心落到半平面外侧，整颗细胞只剩轮廓色，且「弦内」「弦外」读数完全相同。
3. 轮廓必须画在 `|sd| < w` 上而不是 `length(p) ≈ 1` 上 —— 否则弦切面没有边，两细胞接触处缺轮廓。
4. `rebuild()` 新增 `build_geometry` 参数后，`active_count` 不能继续取 `polygons.size()`（shader 路径恒 0），改取 `centers.size()`。
