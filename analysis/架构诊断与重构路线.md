# 架构诊断与重构路线

> 编制于 2026-11-28。基于 Cell Lab 反编译源码（`analysis/cell_lab_apk_extract/decompiled_zh/`）、Alien（chrxh/alien）、Bioneers（Steam 3833810）与现有工程代码的对照。
> 结论：现有架构存在结构性过度设计，即使照抄 Cell Lab 的机制也不该这么慢。可以大改。

## 0. 量化差距（最硬的证据）

| 场景 | 本项目 | Cell Lab | 差距 |
| --- | ---: | ---: | ---: |
| 3000 细胞整 tick | ~250ms+（碰撞 108 + 神经 84 + 环境 46） | **16ms**（60fps） | **15×** |
| 3000 细胞碰撞单项 | 108ms（36µs/细胞） | 全 tick 才 16ms（5.3µs/细胞） | 单项就 6.8× |
| 1024 细胞单 tick（v0.46 优化后） | 12.1ms | — | — |

**超线性爆炸**：本项目 1024 细胞碰撞 3.5µs/细胞，3000 细胞 36µs/细胞——细胞密度涨 3×，每细胞成本涨 10×。Cell Lab 同样规模是线性可控的。

## 1. 五个结构性问题

### 问题一：碰撞求解过度刚性（最大头，占 3000 细胞 43%）

| | 本项目 `resolve_collisions`（native/src/cell_spatial.cpp:281-353） | Cell Lab `c(boolean,double)` + 速度积分（CellWorld.java:1346-1400, 898-967） |
| --- | --- | --- |
| 迭代 | **6 轮** + 每 3 轮 `build_pairs()` 全量重建网格 | **单轮**，每对只处理一次（`i7 > i`） |
| 邻居来源 | 全局 `std::vector<int> pairs` 动态分配 | 固定容量网格 `aV[格][203]`，就地遍历 |
| 修正方式 | **直接改位置**（Gauss-Seidel），位置变了必须重建网格 | 相交面积算**软弹力**，力累积到速度 `cell.g += d60`，位置下一阶段积分 |
| 距离判据 | 每 pair `std::sqrt` | 先用 `d46 < d49*d49` 比平方，确认重叠才 sqrt |

**根因**：本项目追求"单帧刚性收敛"，所以 6 轮迭代 + 位置直接修正 + 重建网格。Cell Lab 用"软弹力 + 速度累积 + 时间自然分离"，单轮就够，视觉上细胞本来就是软的。**这是 6× 起步的结构性浪费。**

### 问题二：数据布局 SoA + 动态字符串访问

- 本项目：SoA 列（`CellArray.gd:13-51`），热路径每 tick 多次 `cells.get("cell_pos_x")` 动态调用 + PackedArray COW 语义。
- Cell Lab：AoS 紧凑 `Cell` 对象 + 固定容量池 + 尾槽换删（`x[i].a(x[z-1]); z--`），全程不 new。
- 影响：缓存局部性差、GDScript→native 胶水开销、跨线程 COW 撕裂风险（B3 已踩坑）。

### 问题三：缺少"昂贵逻辑降频 + 每对象工作量硬上限"

- Alien：`TIMESTEPS_PER_CELL_FUNCTION=6`（神经/基因每 6 tick 算一次）、`MAX_OBJECT_CONNECTIONS=6`、`NEURAL_NET_INPUTS=16`——给每对象工作量设硬上限，昂贵逻辑错峰。
- 本项目：1× 时每 tick 全量 behavior/physics/metabolism；LOD 只在 ≥8× 降频。连接上限 20（与 Cell Lab 同），但**没有神经/行为的固定降频**。
- 影响：低倍速也背满额成本；神经 84ms/3000 细胞（28µs/细胞）远超理论值，说明间接开销巨大。

### 问题四：GPU 几乎闲置

- Alien：CUDA Graph 整步发射（`physics_fillGrids → ... → cell function → structuralOperations`），全程 GPU，每步只同步一次。
- 本项目：GPU 只做环境场扩散/采样（`EnvironmentField.gd`），behavior/physics/metabolism 全在 CPU。
- 影响：浪费 GPU 算力——这正是你最初的判断。

### 问题五：模拟与渲染未真正解耦

- Cell Lab：单后台线程 `ThreadPoolExecutor(1,1)` 跑 update1/update2，渲染线程只做 GL，`Thread.sleep` 锁 60fps。
- Alien：`EngineWorker::runThreadLoop()` 独立线程，默认与渲染解耦。
- 本项目：主线程 tick；B3 的 worker 只是把整个 tick 搬到另一线程，**没解决单 tick 成本**（实测 512 仅 1.21×）。

## 2. 重构路线（按 ROI 排序）

### 阶段 1：碰撞内核重构 —— Cell Lab 式单轮软弹力（最高 ROI）—— **已完成 v0.47.0**

- 把 `resolve_collisions` 从"6 轮迭代 + 重建网格 + 直接位置修正"改为"单轮遍历固定网格 + 相交面积软弹力 + 力累积到速度"。
- 预期：3000 细胞碰撞 108ms → **15–25ms**（参考 Cell Lab）。
- 代价：物理手感变"软"（Cell Lab 就是这个手感，可接受）；**state hash 必须重建**（物理结果不同）。
- 确定性：软弹力用 double 累积、遍历顺序固定，可保同种子可复现。

**落地结果（2026-11-28，v0.47.0）**

实际收益远超预期，且关键杠杆不是"去掉 6 轮迭代"，而是**网格尺寸**：

| 项 | 旧路径 | 新路径 | 倍数 |
| --- | --- | --- | --- |
| 微基准 1024 细胞（等密度） | 1732.3 µs | 71.7 µs | 24.2× |
| 微基准 3000 细胞 | 9367.8 µs | 229.0 µs | 40.9× |
| 微基准 5000 细胞 | 22990.2 µs | 407.0 µs | 56.5× |
| **真实皿 1024 细胞 `phys_collision`** | 1795.1 µs | **109.5 µs** | **16.4×** |
| **真实皿 1024 细胞整 tick 墙钟** | 8800.6 µs | **6869.0 µs** | -21.9%（TPS 113.6→145.6） |

1024 细胞整 tick 墙钟**首次进入 8 ms 预算**（6.87 ms）。碰撞占整 tick 从 20.4% 降到 1.6%，不再是主项。

**分解收益来源（重要，避免后续误判）**：

1. **网格尺寸**（最大单项，约 2.5×）：旧路径 `cell_size` 写死 64.0，而典型细胞直径只有 14。每个桶挤约 20 个细胞，9 格邻域要扫 180 个候选，其中只有约 6 个是真邻居 —— 30× 无效扫描。改为按 `2 × cell_radius × 最大半径倍率` 自动推导（1024 细胞时 13.28，3000 细胞时 7.76）。
2. **去掉 6 轮迭代 + pairs 物化**（约 6×）：单轮遍历，不建 pairs 向量，省掉每 tick 数万次 `push_back`。
3. 两者相乘即 20–50×。

**手感验证**：软弹力最坏重叠 4.62 单位，旧路径 8.44（contact = 14）；平均重叠 0.679 vs 0.437，差 1.7%，肉眼不可辨。细胞数与总能量两条路径完全一致。`COLLISION_SOFTNESS=1.0`（每 tick 消除一半穿透）。

**未做但值得做的后续**：真实"力累积到速度"（Cell Lab 的 `cell.g += d60`）没有采用，改用了位置投影 + 部分修正。原因是本项目 Verlet 的速度是 `pos - prev` 派生，直接投影位置在 PBD 语义下已经等价于注入速度，且比显式冲量更稳定（不会因穿透深度大而爆能量）。若后续上 GPU，才需要显式的速度累加形式。

### 阶段 2：热路径 AoS 化（中等 ROI）

- 把碰撞/邻域/物理的热路径改成 AoS 紧凑结构（每细胞固定 stride 的 Float32 缓冲），减少 PackedArray 间接访问。
- SoA 保留为存档/渲染/Agent 接口。

### 阶段 3：调度层 —— 昂贵逻辑降频 + 工作量硬上限（低成本）

- 参考 Alien `TIMESTEPS_PER_CELL_FUNCTION=6`：神经/行为按固定间隔更新，中间 tick 复用（已有 `should_update_neural` 机制，但只在 ≥8× 生效；可改为全档位固定间隔）。
- 每细胞接触数硬上限（已有 20，可降到更合理的值）。

### 阶段 4：GPU 主体化（长期，最大工程）

- 参考 Alien CUDA Graph：behavior（纯 SIMD，8→4→6 网络）+ collect_inputs_grid（整数邻域计数可保位）搬 GPU compute。
- 需重建 hash 基线；collision 的 Gauss-Seidel 依赖是最大障碍，需先做阶段 1 软化后才可能上 GPU。

## 3. Bioneers 的定位

Bioneers（Steam 3833810，Azza Apps）是"工厂建造 + 器官模拟"玩法向参考：细胞类型（muscle/skin/fat/bone/nerve）连成呼吸/消化/排泄系统 + 神经系统。系统要求 i5-10400F + GTX 1050 Ti，是**中小规模、器官级**模拟，不是几千细胞粒子模拟。**技术架构参考价值有限**，但对本项目的"细胞类型分化 + 器官系统 + 神经网"玩法完成度有直接参考。

## 4. 建议的第一步

先做**阶段 1 碰撞内核重构**：它是 3000 细胞最大单项（108ms/43%），且是超线性爆炸的根源。先在一个隔离原型里实现 Cell Lab 式单轮软弹力，与现有多轮路径做 A/B（同细胞数、同密度），测真实加速比 + 视觉稳定性，再决定是否落地生产 + 重建 hash 基线。

**注意**：这是玩法手感 + hash 基线双重变更，需你确认"接受软弹力手感 + 重建 hash 基线"后才落地生产代码。
